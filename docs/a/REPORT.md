# A 阶段报告：局部条件差分与边界输入

## 方法与设计依据

输入为 before/patch 两个生产源码文件、完整统一 diff、允许的参数基值/长度及候选预算。禁止 oracle/reference/expected_output。首先校验 diff 与输入字节解码后的行一致；使用作者依赖中的 JDT AST，按类名、方法名和参数类型匹配方法，利用修改行定位唯一改变的条件。方法签名/多条件有歧义时拒绝映射。

对局部顺序声明、直接赋值建立参数身份链。例如 `int current; current=score;` 保留 score 的原始参数身份。将 `current>5` 规范化为 `(score, value, >, 5)`，字符串/数组则为 length 度量。常量在左侧时反转比较符。复杂算术、跨函数或控制合流不反推。

生成策略是前后两侧临界值各取 -1/0/+1 的并集，而非仅取补丁一侧。Java int 不允许溢出绕回；负长度跳过；超过 max_length 记录资源限制；多参数仅使用显式配置；数组需显式 fill。去重键包括方法签名和全部有序参数值，合并生成依据。候选预算耗尽须记录尝试截断，不能把没生成解释成无差异。

输出为 a.analysis.v1（见 B_HANDOFF.md），包含条件、直接控制分支的 UTF-16 范围、参数关系、候选、规则、哈希和拒绝原因。supported 是局部语法映射成立；并非覆盖保证、业务合法性或补丁正确性。复杂结构 unsupported，guard 路径未证明时 partial。

## 可讲解的实际生成过程

自建教学例位于 examples/teaching/int-threshold（明确不是实际缺陷统计样例）。完整源码保持不动：

```diff
 int current;
 current = score;
-if (current > 5) {
+if (current >= 5) {
     return 1;
 }
```

AST 定位 teaching.Threshold#decide(int,java.lang.String)，参数声明顺序 score、label；条件第8行。别名链为 score→current。前后边界均为5，尝试4/5/6两次，合并后为三个候选：(4,"allowed")、(5,"allowed")、(6,"allowed")，每个都有两侧依据。label 的基值由请求显式指定，生成器不读取返回答案。

独立验收不只看格式：断言确切条件、方法签名、行号、关联参数、赋值依据、候选值、参数顺序、双侧规则、源码字节哈希；单元测试进一步覆盖不同边界5→8、极值、长度、数组、去重、预算和拒绝性。另从全新项目缓存实际 javac 编译适配器并执行 README 单样例命令。所有步骤退出码、stdout、stderr、耗时保存在新的 handoff-check 目录，历史验收记录不覆盖。

## 真实来源与限制

真实样例纳入规则与排除清单见 REAL_CASES.md。Lang_51 在 A 中保持 unsupported，原版 DiffTGen 的自动反例成果属于既有基线，不是新策略发现。本轮检索的外部生产修复均不满足首版范围；随后 GitHub API 限流，已停止。尚无符合全部规则且取得完整源码对的真实正例。这是 **A 尚欠缺的适配工作**，不能伪装成已完成。

未做全程序影响、符号绑定、跨函数反推、循环/复杂状态、Java8+语法、路径求解、复杂多参数组合。B 未接入前没有三版本新策略运行、oracle 分类、反例缩减或检出率结论。后续 B 判定后才能确认候选是否可执行、区分何种行为、是否回归；C 再对真实合格样例做统计。

## 本次复查的实际修正

原实现会忽略 return 表达式中的未限定外部字段名（例如静态导入 VALUE）。现增加只拒绝不求值的语法检查，避免把未知状态默认为安全。另将适配器超时转为明确 a.error.v1；支持项目 work/a-build 下的新隔离缓存用于干净构建。JSON 字段/版本及共享消费端不变，未修改作者源码或 B/C 完整模块。
